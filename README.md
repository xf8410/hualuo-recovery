# hualuo-recovery（挖掘场）

从 `xf8410/Agora-Workbench`（旧魔改大仓，**只读**）**单向导出**独有代码与证据的地方。
本仓不是产品仓，也不是账本仓：

| 仓 | 分工 |
|---|---|
| `hualuo-foundation` | 只放账：判词、地图、门槛、红线 |
| **hualuo-recovery（本仓）** | **放挖掘现场**：分支快照、补丁、闸门输出、留尸 |
| `hualuo-repo-tool` | 重构落点，只收**已过闸门的成品** |
| `Agora-Workbench` | 证据来源，铁律只读，本仓永不回写它 |

## 为什么需要这一层

旧大仓 124 条非 main 分支里，**22 条已完整并入主干，102 条没并入 = 独有资产**。
这些代码既不能直接进 `hualuo-repo-tool`（会把干净仓再污染一次），也不能进
`hualuo-foundation`（那仓不放业务代码），更不能回写旧仓。所以先落这里验。

## 判词四态（每条分支必给一个）

| 判词 | 含义 |
|---|---|
| `LIVE` | 代码在、逻辑对、有测试撑 —— 可进迁移账，搬代码不搬说法 |
| `HALF` | 部分落地（常见：工具类进了、调用点没接）—— 只搬缺的那半 |
| `DEAD` | 刀痕在但改动是坏码（括号/转义逃逸、重复插入、静默失败）—— 不搬 |
| `ORPHAN-ON-BRANCH` | 主干没有、分支头上有 —— **可恢复资产**，按 LIVE/DEAD 再判一次 |

判死不翻案；被砍的进 `invalidated/` 留尸注明原因，不物理删除。

## 三道机器闸门（不采信 README / commit message / 判词）

1. **结构平衡**：被脚本改过的 Kotlin，用词法状态机核 字符串 / 字符字面量 / 行注释 /
   块注释 / raw 三重引号 / `${}` 嵌套 是否配平。不配平直接 `DEAD`——
   「用 Python 改 Kotlin 靠补右括号逃过红 CI」就是死在这一条。
2. **刀痕比对**：17 把 `scripts/apply_*.py` 的 `old/new` 块逐把对主干，特征片段
   **出现次数必须恰为 1**；`>1` = 重放插了两遍（重建根 `cd631d5`「gen_default_value
   字符串重复定义」正是这类疤）；`=0` 且脚本无守卫 = 静默失败。
3. **反向证伪**：往**测试**里注入变异，若仍然绿，说明测试是假的，该条判词作废。
   这条同时防我自己的新闸门变成摆设。

> 闸门 1/3 需要真编译器。本机 proot 沙盒未装（`Sandbox not installed`），
> 所以闸门一律在 CI（有 JDK）里跑，不在本机凭印象判断。

## 目录结构

```
LEDGER.md                124 条分支总台账（谁已并入、谁待挖、判词）
mine/<分支名>/
  meta.json              头 SHA、相对 merge-base 的独有提交数、改动文件表、有无一次性 workflow
  patches/               从该分支摘出的 .patch（只读导出，不改内容、不重放）
  gate/                  三道闸门的原始输出
  verdict.md             判词 + 文件:行号 + run id
invalidated/<分支名>/     判死的留尸
```

## 入仓规矩

1. 只从 `xf8410/Agora-Workbench` 单向导出，**永不回写**该仓，也不动它的分支。
2. 本仓里的任何代码**不算已验证**；进 `hualuo-repo-tool` 必须过 CI 三道闸门 + 装机验收
   （继承旧仓 README 那两条：源码已提交 ≠ 修复完成；CI 成功 ≠ 实机验收）。
3. 每条结论必须带 `文件:行号` 或 run id；没证据的一律写 `UNKNOWN`，不填默认答案。
4. 不脱敏、不丢身份字段（SID / device_id / token 原样保留），保护靠仓库访问控制。
5. 命名：本仓产物不得叫 Agora（旧仓字样只在证据语境里指旧大仓）。
